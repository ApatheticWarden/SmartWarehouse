# Прошивка робота: архитектура (кратко)

`*` = обсуждали, но ты пока не подтвердил.

## Принципы
- `main.cpp`: только инициализация и запуск тасков, никакой логики.
- Нет god object.
- Всё event-driven: события идут через одну очередь FreeRTOS.

## Цепочка
```
Connector (MQTT) -> Parser -> DecisionEngine (+ StateMachine) -> Robot -> HAL -> моторы
```

| Модуль | Роль |
|---|---|
| Connector | держит связь, принимает сырые сообщения, при потере связи кидает событие |
| Parser | разбирает сообщение по типу (telemetry, tasks...) и отдаёт событие |
| DecisionEngine | «мозг»: смотрит на state + событие и решает, можно ли выполнять |
| StateMachine | хранит текущее состояние и переходы |
| Robot | исполняет: `move`, `stop`, `lift`... Сам не решает |
| HAL | моторы отдельно, чтобы крутить мотор без всего Robot |

## Правила
- DecisionEngine вызывает методы Robot, но не владеет им. Robot можно дёргать напрямую (тесты).
- DecisionEngine ничего не опрашивает: спит до события, state хранит как память.
- Пример: state = blocked, пришёл `move` -> отказ.
- Robot и колбэки только кладут событие в очередь, DecisionEngine не блокируется (`*`).
- Coordinator (карта, маршруты) это отдельная будущая штука, не DecisionEngine.

## Состояния (черновик)
unverified (старт), idle/stopped, moving, lifting, blocked (препятствие), fault `*`, disconnected `*`.

## Отказы
- Пропал MQTT -> событие `connection lost` -> стоп и ждать `*`.
- Пропал датчик при движении -> `fault`, аварийная остановка + алерт на сервер `*`.
- Heartbeat/watchdog: таймер раз в секунду шлёт событие, нет данных дольше порога -> `sensor lost` -> `fault`.
- Старт всегда в `unverified`, пока датчики не подтверждены.
- Watchdog в Robot: долго нет команд -> сам `stop()` `*`.
- Два события почти одновременно: побеждает более безопасное `*`.
